# Пояснение ко второй лабораторной

## Что сделано

Интерфейс позволяет:

- зарегистрироваться и войти;
- войти как заказчик или исполнитель;
- создать, изменить и удалить новый заказ;
- принять заказ и отметить его выполненным;
- отфильтровать заказы по статусу;
- изменить имя и email в профиле.

Настоящего сервера пока нет. Обычные сервисы `AuthService` и `OrderService`
работают с тестовыми массивами вместо API.

## Назначение файлов

| Файл | Назначение |
| --- | --- |
| `src/main.ts` | Запускает приложение и подключает роутер |
| `app.routes.ts` | Связывает адреса страниц с компонентами |
| `models.ts` | Описывает пользователя и заказ |
| `auth.service.ts` | Выполняет вход, регистрацию и изменение профиля |
| `order.service.ts` | Хранит тестовые заказы и работает с ними |
| `components/login/` | Форма входа |
| `components/register/` | Форма регистрации |
| `components/order-list/` | Список заказов и кнопки действий |
| `components/order-form/` | Создание и изменение заказа |
| `components/profile/` | Форма профиля |
| `app.component.*` | Общая шапка и место для выбранной страницы |
| `src/styles.css` | Задаёт общие стили страницы |

## Основные понятия

- `interface` описывает поля объекта.
- `type` задаёт набор допустимых значений.
- `@Component` превращает класс в компонент Angular.
- `@Injectable` позволяет передать сервис в компонент.
- `Router` открывает страницу по её адресу.
- `routerLink` создаёт ссылку на маршрут.
- `router-outlet` показывает выбранный компонент.
- `*ngIf` показывает элемент при выполнении условия.
- `*ngFor` повторяет элемент для каждого заказа.
- `[(ngModel)]` связывает поле формы со свойством класса.
- `(click)` вызывает метод после нажатия кнопки.
- `{{ значение }}` выводит значение в HTML.

## Почему email не отправляется

Отправка писем выполняется на сервере. Во второй лабораторной сервера нет,
поэтому регистрация и изменение email только меняют тестовые данные в памяти.
