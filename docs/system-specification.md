# Спецификация системы

## 1. Назначение

Система помогает заказчикам создавать заказы, а исполнителям — принимать и
выполнять их.

## 2. Технологии

- Клиент: Angular и TypeScript.
- Сервер: Node.js, Express и TypeScript.
- Хранилище третьей лабораторной: репозитории-заглушки в памяти.
- Планируемая база данных: PostgreSQL.
- Обмен данными: REST API в формате JSON.

## 3. Роли

### Заказчик

- создаёт заказ;
- изменяет и удаляет свободный заказ;
- просматривает свои заказы.

### Исполнитель

- просматривает свободные заказы;
- принимает один из них;
- меняет статус принятого заказа.

## 4. Состояния заказа

- `new` — новый;
- `in_progress` — в работе;
- `completed` — выполнен.

## 5. Данные

### Пользователь

- идентификатор;
- имя;
- email;
- пароль;
- роль.

### Заказ

- идентификатор;
- название;
- описание;
- срок;
- стоимость;
- статус;
- заказчик;
- исполнитель.

## 6. Основные запросы API

| Метод | Адрес | Назначение |
| --- | --- | --- |
| POST | `/api/auth/register` | Регистрация |
| POST | `/api/auth/login` | Вход |
| GET | `/api/orders` | Получение заказов |
| POST | `/api/orders` | Создание заказа |
| PUT | `/api/orders/{id}` | Изменение заказа |
| DELETE | `/api/orders/{id}` | Удаление заказа |
| PUT | `/api/orders/{id}/accept` | Принятие заказа |
| PUT | `/api/orders/{id}/status` | Изменение статуса |
| GET | `/api/profile` | Получение профиля |
| PUT | `/api/profile` | Изменение профиля |

## 7. Основные страницы

- вход и регистрация;
- список заказов;
- создание и изменение заказа;
- мои заказы;
- профиль.

## 8. Правила

- Неавторизованный пользователь видит только вход и регистрацию.
- Заказчик управляет только своими заказами.
- Исполнитель изменяет только принятые им заказы.
- Принять можно только заказ со статусом `new`.
- Обязательные поля проверяются перед сохранением.
